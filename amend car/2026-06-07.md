## 第五版路线、A1 识别与夹取修正

版本目录：

- 硬件烧录目录：`D:\amend car\2026-06-07_2026v5_route_tag_grip_fix`

现场反馈：

- 底盘走得太歪，不够直。
- 夹东西不准确，抓取动作需要更稳。

核心判断：

- A1 原逻辑只判断第一包 AI 目标数据是否非零，容易被误检或旧数据放行。
- 底盘长距离一次跑完容易累计偏航，且原流程很多底盘动作即使失败也会继续下一步。
- 夹取不准不能先盲改大坐标，本轮先通过减速、停稳、慢夹来提升稳定性，等下一次视频/实体反馈再做坐标标定。

- `amend car/2026-06-07_2026v5_route_tag_grip_fix/2026v1.c`

- A1 需要连续确认 24 轮，并在识别前重新等待 AI 相机模型稳定。

- `go_bmp()` 直线方向增加左右编码器平衡修正，减少左右轮累计编码差造成的跑歪。
- `go_bmp()` 距离判断改为各轮编码器绝对增量，减少编码器方向符号导致的距离误判。
- 所有主路线底盘动作和主要机械臂动作增加失败保护，失败后显示阶段并停止，不再继续硬跑下一段。
- A1 抓取前进距离从 `7cm` 改为 `5.5cm`，速度降到 `20`，下降、夹紧、抬升动作加慢并增加停稳。

## 第六版状态机、底盘斜坡与视觉去噪

- 硬件烧录目录：`D:\amend car\2026-06-07_2026v6_state_retry_vision_filter`

本轮目标：

- 继续处理实车反馈中的三类核心问题：底盘走歪不直、夹取不准、第一步识别 Tag 时未真正识别就继续执行。
- 对用户提出的架构、控制算法、可靠性、可观测性、代码质量问题先做低风险改动，保持工程能直接在 VSCode 编译和烧录。
- 图像识别方面，当前 E7/AI 相机 API 只暴露识别结果数据，暂未看到原始图像帧接口；因此本版先做结果级去噪。若后续能拿到原始帧，再加入高斯模糊、二值化、形态学去噪、轮廓/形状识别。

涉及文件：

- `amend car/2026-06-07_2026v6_state_retry_vision_filter/2026v1.c`
- `amend car/2026-06-07_2026v6_state_retry_vision_filter/go_bmp.c`
- `amend car/2026-06-07_2026v6_state_retry_vision_filter/go_to_tag.c`
- `amend car/2026-06-07_2026v6_state_retry_vision_filter/paw_control.c`
- `amend car/2026-06-07_2026v6_state_retry_vision_filter/hardware_config.c`
- `README.md`

核心改动：

- `go_bmp.c` 重写为更清晰的底盘编码器控制模块，修复 M1 编码器读取被乱码注释吞掉的问题；旧代码中 `vl` 没有实际更新，会直接影响距离判断和左右平衡。
- `go_bmp()` 增加方向参数检查、目标距离检查、轮径/编码器参数检查、速度限幅和运动结束停车。
- `go_bmp()` 增加简单梯形速度规划：起步/收尾按 `ROBOT_ROUTE_RAMP_CM` 降速，减少起步冲击和冲过目标点的风险。
- `go_bmp()` 直行方向持续使用左右编码器平衡修正，减少长距离走歪。
- `go_to_tag.c` 增加识别结果范围过滤：X/Y/角度全零、越界或异常角度都不放行。
- `go_to_tag()` 要求连续 `ROBOT_TAG_NAV_CONFIRM_LOOPS` 帧有效识别后才开始移动，减少单帧误识别导致的误启动。
- `go_to_tag()` 在识别丢失时立即停车并清空稳定计数，避免沿用上一帧电机速度继续偏离路线。
- PID 增加积分限幅和输出限幅，降低视觉角度误差瞬间把旋转速度打满的风险。
- `trace_go_to_tag()` 对 A2/A3/终点 Tag 增加最多 2 次重试，并在屏幕显示 `TAG RETRY`、`TAG OK` 或 `TAG FAIL`。
- 主流程增加阶段状态记录：每个阶段通过 `run_stage()` 执行，屏幕显示阶段号、阶段耗时和 `STAGE OK/STAGE FAIL`。
- `load_navigation_pid()` 对从数据区读取的 PID 参数做边界检查，避免异常存储值破坏控制。
- `paw_control()` 增加夹爪舵机 PWM 和执行时间下限保护，减少误传参数导致的机械动作风险。
- `hardware_config.c` 新增路线斜坡、Tag 重试、视觉样本范围、PID 限幅、舵机 PWM 范围等集中参数。

本轮没有直接做的事项：

- 没有大拆 `#include "xxx.c"` 架构，因为当前比赛工程依赖单文件包含式编译，比赛前贸然改成标准多文件工程风险过高。

## 第七版 A1 识别回退与横移均衡

版本目录：

- 仓库内：`amend car/2026-06-07_2026v7_a1_fallback_strafe_balance`
- 硬件烧录目录：`D:\amend car\2026-06-07_2026v7_a1_fallback_strafe_balance`

现场反馈：

- v6 底盘没有更直。
- v6 到 A1 前没有按预期停稳处理。
- 相机画面可看到 A1/AprilTag，但程序没有继续执行机械臂动作。
- 图像识别阶段会闪一下，然后屏幕显示失败。

核心判断：

- 视频里相机画面能框出 Tag，绿字显示类似 `ID:1`；但控制屏随后显示 `A1 NO ID`，说明相机本身能识别，程序读取 `GetAICamIDData()` 的方式与现场相机数据接口不匹配，或放行条件过严。
- v6 对 A1 坐标做了固定范围过滤，而现场坐标系未确认，这可能把真实识别结果误判为无效。
- v6 主要给直行方向做平衡，开局第一段是横移，横移仍可能因为四轮进度不一致导致车身歪。

涉及文件：

- `amend car/2026-06-07_2026v7_a1_fallback_strafe_balance/2026v1.c`
- `amend car/2026-06-07_2026v7_a1_fallback_strafe_balance/go_bmp.c`
- `amend car/2026-06-07_2026v7_a1_fallback_strafe_balance/go_to_tag.c`
- `amend car/2026-06-07_2026v7_a1_fallback_strafe_balance/hardware_config.c`
- `README.md`

核心改动：

- A1 识别主判断从 `GetAICamIDData()` 回退为 `GetAICam(ROBOT_AI_CAM_PORT, 1, cmd)`，按第 1 个目标读取 ID、X、Y、角度。
- A1 放行条件改为：连续 6 帧读到 `ID=1`，且 X/Y/角度不是全 0，即认为看到 A1，继续后续动作。
- A1 前不再重新调用 `SetWaitAICamCmd()` 切换模型，只使用主程序初始化时已经配置好的视觉模型，减少识别点闪屏和数据重置。
- A1 屏幕调试显示改为：第 1 行显示读到的 ID，第 3 行显示 X，第 5 行显示稳定帧计数。
- A2/A3 的 `go_to_tag()` 识别过滤放宽：不再使用固定 X/Y 范围，只过滤全 0 和异常角度，避免坐标系假设错误。
- `go_bmp()` 新增 `balance_direction_speed()`，对直行、横移、斜移的活动电机都按编码器进度做均衡，不再只处理直行。
- 底盘速度进一步保守：路线最大速度从 `24` 降到 `18`，转向上限从 `26` 降到 `22`。
- 长距离分段从 `24cm` 降到 `12cm`，动作后停稳时间从 `0.18s` 增加到 `0.25s`。
- 编码器均衡增益从 `0.03` 提高到 `0.06`，均衡限幅从 `5` 提高到 `7`。
